# Real Runtime Landing Demo Design

## Objective

Replace the GitHub Pages landing page's hand-authored Credit Monitor mock with the real v0.7.2 presentation/runtime code running against simulated local data. Redesign the landing presentation inside the established **Instrument Panel / Confidence Layer** world without changing the published extension, manifest, collector, synchronization behavior, storage schema, permissions, or release archive.

## Approved Decisions

- Surface mode: Persuade.
- Visual direction: preserve and strengthen Instrument Panel / Confidence Layer.
- Build path: code-led.
- Runtime strategy: isolated iframe that loads generated byte-identical mirrors of canonical `/src` files.
- Demo truth: real Credit Monitor UI and behavior; simulated usage values; no Lovable connection.
- Initial data: `used: 1267`, `limit: 1400`, `source: "people"`, current dynamic month, recent observation time.
- Manual sync result: `used: 1274`, `limit: 1400`, delivered after a deterministic delay between 600 and 1000 ms.
- Existing uncommitted changes that only repair the obsolete fake demo may be superseded by stronger real-runtime tests. Unrelated working-tree changes must remain untouched.
- Brand inputs: use the supplied `lovable.svg` and `github.svg`; the GitHub mark renders pure `#FFFFFF` in every state.

## Non-Goals

- Do not redesign or modify the installed browser extension.
- Do not add a bundler, CDN, remote runtime, analytics, tracking, or network dependency.
- Do not reproduce Lovable as a factual screenshot or connect the demo to a Lovable account.
- Do not introduce landing-owned controls for view, settings, palette, or theme.
- Do not manually recreate Credit Monitor markup, CSS, state transitions, or animations.

## Architecture

### Canonical Runtime Mirror

`src/panel.css`, `src/state.js`, `src/collector.js`, `src/brand.js`, `src/icons.js`, `src/sync.js`, and `src/content.js` remain the only authored runtime sources. `scripts/sync_demo_runtime.py` copies them byte-for-byte into `docs/demo/runtime/` and supports both synchronization and check-only verification. The deployable copies are generated artifacts, never edited directly.

`scripts/verify_repository.py` compares every required source/mirror pair by SHA-256 and fails on missing, extra, or mismatched runtime files. Tests exercise the synchronization script in both success and drift cases.

### Iframe Runtime

`docs/demo/index.html` is the single demo entry point used by both the hero preview and the main interactive section. It loads:

1. `demo-workspace.css` and `runtime/panel.css`.
2. The real runtime dependencies in production order: `state.js`, `collector.js`, `brand.js`, `icons.js`, and `sync.js`.
3. `demo-adapter.js`, which preloads data and defines the required `globalThis.chrome` surface.
4. The real `runtime/content.js`, which initializes normally and owns all Credit Monitor UI.

The iframe URL may use a presentation-only query parameter such as `surface=hero` to adjust the simulated workspace crop. It must not change Credit Monitor behavior or product state semantics.

### Demo Adapter

The adapter implements only:

- `chrome.storage.local.get`
- `chrome.storage.local.set`
- `chrome.storage.onChanged.addListener`
- `chrome.runtime.sendMessage`

Storage is an in-memory object scoped to the iframe. `local.set` emits Chrome-shaped change records to registered listeners. The initial usage month is produced by the real `LCMState.monthKey(new Date())`, and runtime storage keys come from the canonical runtime where exported.

`runtime.sendMessage` handles only the messages emitted by `content.js`. Registration/activity messages resolve harmlessly. `LCM_MANUAL_SYNC` resolves asynchronously after 800 ms, writes the updated usage and healthy sync state through `chrome.storage.local.set`, and therefore lets the real storage listener drive count-up, progress, pulse, sync status, and visual feedback. Reloading the iframe deterministically restores the initial state.

No Chrome call leaves the iframe, and no network request is made.

### Simulated Workspace

The iframe body contains a restrained Lovable-like desktop workspace: project header, sidebar, editor/build surface, and conversation/canvas context. It uses the supplied Lovable SVG and contains only fictional project information. A persistent but quiet label reads **Real interface · simulated usage data**.

The workspace provides space for the runtime's fixed-position panel to drag, clamp, and respond to viewport edges. It does not style elements below `#lcm-panel` except through the mirrored `panel.css`.

## Landing Page

### Direction Contract

The first child of `<body>` remains an auditable comment with the existing seed `690409fa` and an updated first-viewport promise: the product message and actions occupy the left side; a live real-runtime iframe occupies the right; a compact trust rail closes the viewport. The page preserves near-black instrument surfaces, scarce cyan telemetry, green confirmation, fine evidence lines, tabular values, and restrained depth.

### First Viewport

The hero presents:

- Credit Monitor brand and unofficial-extension context.
- “Lovable credits, always in view.”
- One concise benefit statement.
- Primary v0.7.2 ZIP download and secondary “Explore demo” action.
- Chrome/Edge, local-only, source-visible, and unofficial trust evidence.
- A real-runtime hero iframe cropped as a polished desktop instrument preview.

The obsolete `AVAILABLE / 36 credits` composition is removed entirely.

### Main Demo

The main demo section contains an informative iframe titled **Interactive Credit Monitor demo** and no external view, palette, theme, or appearance controls. Visitors interact with the runtime-rendered buttons inside `#lcm-panel`. Supporting copy states that the interface/runtime is real, usage values are simulated, the page never connects to Lovable, and the installed extension uses Settings > People as its authoritative source.

On mobile, the desktop iframe is proportionally framed or scaled within a clipping container. The page never presents the extension as a mobile product and never allows horizontal document overflow.

### Evidence Journey

The remainder of the page keeps the current persuasive sequence while removing duplication:

1. Hero and trust rail.
2. Animated People → local storage → workspace evidence path, using the Lovable brand at the source step.
3. Real interactive demo.
4. Three capability/evidence groups.
5. Privacy boundary and focused permissions.
6. Truthful three-step manual installation.
7. Final download action and source/footer links.

All non-brand interface icons use filled Boxicons, reusing canonical paths from `src/icons.js` where available. No emoji, outline-icon mixture, or text glyph substitutes remain.

## Motion and Interaction

Landing motion uses opacity and transforms: staggered hero entry, slow instrument orbit, restrained desktop pointer perspective, IntersectionObserver section reveals, sequential evidence-rail illumination, and 1–2 px button lift/press feedback. The iframe frame may receive a subtle neutral response to focus, but the landing never duplicates product animations.

The real runtime exclusively owns count-up, progress fill, ring transition, mode morph, sync spin/pulse, theme changes, settings expansion, drag behavior, and the one-second reset countdown.

Under `prefers-reduced-motion: reduce`, the landing disables continuous orbit, parallax, reveal translation, decorative pulses, and smooth scrolling. Content remains visible without JavaScript. The mirrored extension CSS retains its existing reduced-motion rules unchanged.

## Accessibility and Responsiveness

- Semantic header, main, sections, footer, one `<h1>`, and logical heading order.
- Descriptive iframe titles and concise accessible brand treatment.
- Visible `:focus-visible` states and 44 px minimum landing touch targets.
- GitHub mark remains pure white at rest, hover, focus, and active states.
- WCAG AA text contrast and no color-only state communication.
- Responsive validation at 1440, 1280, 1024, 768, 430, and 375 px.
- No horizontal page overflow; technical strings wrap safely.
- Keyboard users can reach the iframe and operate the runtime's real buttons.

## Test Strategy

### Automated Contracts

- Landing markup contains no `.credit-monitor`, `.monitor-full`, `.monitor-compact`, `.monitor-minimal`, `.monitor-ring`, external `[data-view]`, or external palette/theme controls.
- `docs/demo.js` contains no independent usage/view/theme/palette state and does not query or mutate `#lcm-panel`.
- Hero and main iframe paths resolve inside `/docs`; the main iframe has the required accessible title.
- Demo HTML loads every generated runtime dependency and loads `content.js` after the adapter.
- Adapter source exposes only the four approved Chrome capabilities and contains no fetch, XHR, beacon, WebSocket, or external URL.
- Adapter storage events have Chrome-compatible `{oldValue, newValue}` records and manual sync deterministically changes `1267` to `1274` through storage.
- Canonical `content.js` remains the source containing view cycle, minimal/ring surfaces, settings, palette/theme, Sync, countdown, and drag event ownership.
- Every generated mirror is SHA-256 equal to its canonical source; deliberate drift fails both the sync check and repository verification.
- Supplied Lovable and GitHub files are used, and the GitHub SVG's visible path is `#FFFFFF` or `currentColor` under an explicitly white container.
- Download link still references the exact v0.7.2 ZIP and repository verification still checks the archive.

### Browser Verification

Serve `docs/` locally and use browser automation for a single bounded desktop/mobile inspection round followed by at most one batched correction round. Verify:

- Full → Compact → Minimal; Minimal click → Compact; Minimal double-click → Ring; Ring click → Minimal.
- Appearance drawer; Original, Red, Juparanã, and Black & White palettes; Auto, Light, and Dark themes.
- Syncing state, delayed storage update, count/progress/status/pulse response.
- Live countdown changes after one second.
- Dragging and edge clamping inside the iframe.
- Keyboard navigation, focus visibility, reduced motion, and console cleanliness.
- Layout at every required width and GitHub/Lovable asset rendering.

## Acceptance Criteria

- The landing page contains no second implementation of Credit Monitor.
- The product shown in both previews is created by the real mirrored `content.js` and styled by the real mirrored `panel.css`.
- Only the browser APIs and usage data are simulated.
- Runtime drift is impossible to miss in tests and repository verification.
- A visitor can operate every required product interaction from inside the monitor.
- The page clearly distinguishes real interface/runtime from simulated usage and makes no Lovable connection claim.
- The first viewport is significantly stronger while remaining recognizably Instrument Panel / Confidence Layer rather than a generic SaaS or neon developer-tool template.
- The extension source, manifest, permissions, storage schema, sync behavior, collector behavior, and distribution ZIP remain byte-for-byte unchanged.
